# From text to editorial decision

This is a walkthrough of the *process*, not an assertion that every candidate was published or approved.

## Example: retain an authentic hesitation

**Author's draft (direct writing):**

> Vamos a utilizar el nombre de marketing engineer, aunque yo de ingeniero tengo poco. Pero nos sirve para que todos nos entendamos. Yo casi que me lo llevaría mucho más hacia un Brand Engineer

**Editorial observation:** The author questions the label while using it. That is part of the argument, rather than something to clean away.

**Derived guideline:** Preserve authentic hesitation, contextually grounded humor, and reservations about terminology; correct errors without replacing a person's voice with a corporate definition.

**Later application (illustrative, not an observed approved revision):** When editing a role description, don't automatically replace "aunque yo de ingeniero tengo poco" with "perfil innovador en la intersección de disciplinas". Keep the author's own framing unless they explicitly ask for a formal definition.

## Example: learn from feedback in both directions

**Explicit feedback 1:** "Hay demasiadas frases indivudlaes y poco párrafo. Corrige eso."

**Explicit feedback 2:** "Ahora hay demasiado párrafo y poca frase. Neceisto musicalidad."

**Editorial observation:** A rule based only on the first message would be misleading; together the messages imply varied, natural rhythm.

**Derived guideline:** Alternate sentence and paragraph length in context; don't enforce an arbitrary number of lines or words.

**Application:** A technical article should have breathing room for developed arguments and short sentences only where emphasis helps.

## Example: prioritize a concrete decision

**Coedited version 1:**

> Decir que GLM es "el Claude abierto" o que DeepSeek sustituye a GPT sirve para orientarse, pero no para decidir realmente.

**Coedited version 2:**

> Decir que GLM es «el Claude abierto» o que DeepSeek sustituye a GPT sirve para orientarse, pero no para decidir qué poner en producción.

**Editorial observation:** The later version names the actual deployment decision; it doesn't need more marketing language.

**Derived guideline:** Replace vague abstraction with concrete consequences for the reader where the source supports it.

**Evidence caveat:** This is a comparison between document versions. We do not claim each change was explicitly approved by the author.
